# ECG 后端模块化代码完善待办

本文依据[外设与代码架构](./外设与代码架构.md)以及当前 `Core`、`cmake` 代码整理。目标是在保留 CubeMX 外设初始化代码的基础上，逐步完成连续 ECG 采集、处理、心率计算和 LCD 展示。

## 代码组织建议

建议采用**功能模块分别放在 `.h/.c` 文件中，`main.c` 负责初始化和调用**，而不是把所有逻辑堆在 `main.c`：

| 方案 | 优点 | 风险与适用范围 |
|---|---|---|
| 每个功能模块使用 `.h/.c` | 职责清晰；模块状态可在 `.c` 内部维护；接口明确；便于分模块验证和后续替换 | 需要维护接口和构建源文件列表；适合本项目这种持续采样、多阶段处理和显示并行的固件 |
| 所有逻辑放在 `main.c` | 初期文件少、简单演示上手快 | 主循环和中断回调容易膨胀；滤波器、RR 间隔、绘图状态相互耦合；难以验证 DMA 块边界行为；适合短小的一次性验证程序 |

**推荐结论：**按采集、信号处理、心率/事件、按键和显示拆分模块。`main.c` 保留 HAL/时钟/外设初始化与高层调度，不承载具体算法；中断回调保持短小，只记录就绪事件或转交给对应模块。CubeMX 生成文件尽量只在 `USER CODE` 区域扩展，避免重新生成时丢失改动。

建议逐步形成如下结构（模块名可按实现调整）：

```text
Core/
  Inc/
    ecg_acquisition.h
    ecg_signal.h
    ecg_rpeak.h
    heart_rate.h
    ecg_measure.h
    key_input.h
    ecg_display.h
  Src/
    ecg_acquisition.c
    ecg_signal.c
    ecg_rpeak.c
    heart_rate.c
    ecg_measure.c
    key_input.c
    ecg_display.c
```

`.h` 只公开模块需要的类型、常量和函数；缓冲区、滤波状态、按键消抖状态及绘图指针等内部状态原则上留在对应 `.c` 文件。新增 `.c` 文件后同步加入 CMake 可执行目标。

> **Git/依赖说明：**按项目要求，`Drivers/` 不纳入 Git。当前 CMake 配置直接引用该目录中的 HAL、CMSIS-DSP、LCD 和 DELAY 源码，因此在其他工作区构建前，必须由本地提供兼容的驱动文件；CMake 配置、工具链文件和链接脚本则应保留在版本控制中，以复现构建过程。

阶段 1 配置记录：系统时钟为 100 MHz，APB1 分频为 4，因此 PCLK1=25 MHz；APB1 定时器时钟在分频不为 1 时为 2×PCLK1=50 MHz。TIM2 PSC=9、ARR=499，更新频率为 50 MHz / ((9+1)×(499+1)) = **10 kHz**。ADC circular DMA 缓冲区为 512 个 `uint16_t` 样本，分为两个 256 点半区；每个就绪块覆盖连续 25.6 ms。DMA 回调只发布事件及块起始样本计数，主循环按半区顺序取块、处理后释放；当 DMA 即将重新写入未释放/未消费的半区时记录覆盖故障，主循环转入错误处理。32 位无符号样本计数按块递增，约 4.97 天自然回绕；下游差值应采用无符号减法。LED 和最坏处理耗时仍需目标板实测。
