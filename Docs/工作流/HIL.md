# 角色与任务
你是一位资深的嵌入式测试架构师。请根据我提供的【模块化业务代码】，为我设计一套基于硬件在环（HIL）的自动化/半自动化测试方案。

# 核心工程原则（必须严格遵守）
1. **编译期隔离（零开销）**：测试代码绝不能污染量产固件。必须使用预处理器宏（如 `#ifdef`）包裹，确保在 Release 构建中物理剔除，不占 Flash/RAM，不产生运行时分支。
2. **用好测试钩子（Test Hooks）**：
   - **观测**：添加全局变量（如 `g_test_xxx`）记录内部状态，供调试器（Watch 窗口）读取。
   - **校验**：在数据流的关键路径（如主循环消费、中断回调）插入断言逻辑（如块长校验、序号连续性校验）。
   - **干预/注入**：提供宏或变量，允许测试时强制修改初始状态（如计数器起点、故障标志）。
3. **用 CMake Preset 管理变体**：利用 `CMakePresets.json` 的 `hidden` 和 `inherits` 属性，定义基础 Debug 预设，并派生出不同的测试场景（如长跑测试、边界回绕测试、故障屏幕测试）。

# 输出要求（请按以下结构生成）
## 1. 业务代码改造（测试钩子注入）
- 分析业务代码的核心数据流和状态机。
- 定义必要的测试观测变量、校验逻辑和注入点。

## 2. CMake 构建系统配置
- 给出 `CMakeLists.txt` 中通过 `option()` 和 `target_compile_definitions()` 控制测试宏。
- 提供完整的 `CMakePresets.json` ，建议包含：
  - 一个隐藏的 `debug-base`。
  - 派生出的 `Debug-NormalTest`（验证正常逻辑）。
  - 派生出的 `Debug-BoundaryTest`（通过宏注入极端起点，如 0xFFFFFF00，测试溢出）。
  - 派生出的 `Debug-FaultTest`（强制进入错误处理路径）。

## 3. HIL 测试执行指南（人工或自动化脚本）
- 针对每个测试 Preset，写一段操作说明（构建->刷写->运行时长->暂停查看什么变量->预期结果）。
- 强调测试完成后的清理动作（重新刷写正常固件）。

# 本项目约定

- 主机测试统一放在 `Tests/`，单独配置并由 CTest 运行；不需要使用固件/HIL presets。硬件测试不伪装成可在主机上执行的 CTest 用例。
- 每种目标板测试场景使用独立的 CMake configure/build preset。当前包含 `HILValidation`（采集与信号链观察）和 `HILFilterFault`（滤波故障显示）。
- HIL 测试需要目标板、调试器及场景所需外部设备，按对应 HIL 验证文档手动构建、烧录、运行，并通过 Watch/捕获数据核验。完成故障测试后恢复普通固件。
